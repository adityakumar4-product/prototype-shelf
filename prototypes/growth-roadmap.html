Part 1 — Growth loop framework and flow charts

1. Purpose

A single, product-owned journey that moves every new signup through activation, conversion, and retention over 30 days, with CLM as the delivery channel rather than the owner. Each user sits in exactly one state at any time; the state and the day since signup decide what the product shows and what comms go out.

2. Definitions

Term Definition Baseline Target
Soft activation Explored any SKU (batch detail, free content, Pi, books) ~60% by D7 65–70% by D7
Hard activation First paid conversion 8.2% 8.65% (+5% relative)
Conversion window Main batch (₹4–5K) pushed as primary SKU — D0–D15
Digital window Pi, Digital Books, PW Talks pushed as primary SKU — D15–D21
Free window Free batch enrolment, then Master Any Topic — D21–D30

Observed conversion timing: 72% of all D30 conversions happen by D7, 87% by D15. Exploration moves only ~3.4 pts between D7 and D30.

AOV ladder (descending): Main batch → Low-AOV / Digital → Free batch → Free content. Step down only after the window above has closed.

7. Free batch journey (D21+)

Visibility ramp: free-batch real estate on home and comms intensity both rise as a function of days-since-signup × conversion state.

Comms loops: teacher + topic specific ("Learn Optics from Rajwant sir for free"); coins while learning, redeemable on paid purchase; rotating free-content touches, capped.

In-batch upsells (A/B tested):

Lecture backlog N lectures behind Backlog Killer combo (Pi + Digital Books + Quiz)
Low DPP / test score Below cohort median Increase Your Marks package
7-day streak Engagement One-time paid-batch discount

8. Master Any Topic (D21+, non-enrollers)

Unstructured learning surface: 2 topics/day free, more requires subscription (Pi or Pi + Books bundle). Topics seeded from goal + explored batch; daily reset notification as a return trigger; "go deeper" CTA opens the free-batch lecture on the same topic; coins and streaks shared with the free-batch economy.

9. Loop C — Buyers

D0: onboarding into batch (first lecture, schedule, test calendar). First milestone: referral link. D7–D15: cross-sell (test series, books, FBT). Thank-you page digital gift offer. Season start: next-year purchase / 2-year combo. Feeds retention.

10. Event triggers (override the day clock)

  • Propensity high + no purchase 48h → 72h discount
  • Back click on detail / checkout → bottom sheet (free lecture or counsellor)
  • Payment failure → WA/SMS retry link within minutes, alternate methods, max 3 touches in 24h
  • Cart abandon at payment → WA payment link within 15 min
  • Batch start T-3 / price change T-2 → urgency to all who saved/viewed
  • Free content consumed ≥2 pieces in a cohort → reclassify as explored, move to Loop B
  • Any purchase → immediate exit from Loops A/B into Loop C

11. Seasonality config

Journey lengths are a cohort × season parameter, not fixed days.

Season Activation window Conversion window Digital window Discount timing
March (session launch) D0–D2 D0–D3 D3–D7 D1
Apr–May D0–D5 D0–D10 D10–D15 D5
Jan–Feb, Jul–Aug D0–D7 D0–D15 D15–D21 D7

The cohort's exam/session calendar sets the window — a UPSC aspirant and an 11th JEE student signing up the same week are in different seasons.

12. Guardrails

  • Frequency: max 1 push + 1 WA per user per day; ≤4 WA per week
  • Discounts gated by propensity and day; no blanket discount before D7
  • Holdout per step for attribution
  • Reclassification is automatic and immediate
  • Daily engagement reminders (Master Any Topic) only for users active in the last 3 days

Communication load till D30

Uncapped, the worst-case path (never explores → never converts → digital ladder → free batch → Master Any Topic) would receive roughly 30–35 scheduled and triggered touches in 30 days. The recommended ceiling is 14–16 touches, front-loaded where conversion happens:

Window Touches Rationale
D0–D7 6 72% of conversions land here
D8–D15 4 15% of conversions; one every two days
D16–D21 3 Digital ladder — collapse to Pi → ₹99 combo → trial if the cap binds
D22–D30 2–3 Free-batch invite + one topic nudge; MAT daily reset only for users active in the last 3 days

Rules: hard cap 1 push + 1 WA per day and ≤4 WA per week; event triggers count against the cap and replace that day's scheduled touch; an in-app visit suppresses the scheduled push; three unopened pushes drop the user to WA-only at half frequency, three unopened WAs go silent until D30; converters exit the schedule instantly. First comms holdout: 14 vs 10 touches.

Scoring legend

  • Reach (R): % of the theme's base population touched per month. Base differs by theme — see "Reach basis". Scores are comparable within a theme, not across themes.
  • Impact (I): 0.25 minimal · 0.5 low · 1 medium · 2 high · 3 massive, on the theme's metric
  • Confidence (C): 0.4 guess · 0.5 weak · 0.6 some evidence · 0.7 reasonable · 0.8 strong
  • Effort (E): engineering person-weeks incl. design and analytics
  • Score = R × I × C ÷ E
  • Source: A = Aditya · C = Claude · A/C = Aditya's item, Claude-extended

Reach bases: Uninstall = new installs · Activation = new signups · Conversion = explored-not-converted · ARPU = paying users (or free-batch enrollers where noted) · Retention = non-converted users alive at D15 · Others = n/a (enablers).

Theme 1 — Uninstall

U01 — Defer / skip name input

  • What: Remove the name screen from the signup → listing path; ask for name later (first purchase, profile, or a "complete your profile" nudge after D1).
  • Why: Every screen between signup and value is a drop point; name adds no value to the student at that moment and is the cheapest step to remove.
  • Where: Onboarding, between signup success and goal selection.
  • How: Feature flag the screen off; default display name to "Student"; collect name at checkout address or on D1 home card.
  • Depends on: Nothing material. Check downstream systems that assume a name exists (certificates, leaderboards).
  • Metric: Signup success → goal selection rate; D0 uninstall.
  • Risk: Minor — personalisation copy ("Hi Aditya") loses a name until collected.

U02 — Notification permission prompt after first value

  • What: On Android 13+, request notification permission after the user has seen a batch or watched a demo clip rather than on first launch.
  • Why: Permission prompts on cold launch raise early abandonment and are denied more often; asking after value increases grant rate and reduces the "what is this app" friction.
  • Where: First session, after the user reaches batch listing or taps a batch.
  • How: Gate the OS prompt behind a product event (listing viewed or demo played) with a pre-prompt explaining what notifications will contain.
  • Depends on: Android 13+ handling already exists; iOS already behaves this way.
  • Metric: Permission grant rate; D0 uninstall; D1 push reach.
  • Risk: Users who uninstall before the prompt never get asked — acceptable, they were leaving anyway.

U03 — OTP auto-read root-cause fix

  • What: Diagnose why only ~50% of OTPs auto-read and fix it; add WhatsApp OTP or Truecaller as a fallback.
  • Why: Manual OTP entry is a friction point before the user is even "signed up"; it is excluded from the 20% uninstall figure, so the real top-of-funnel loss is understated.
  • Where: Mobile number → verification.
  • How: Audit SMS Retriever hash correctness per build variant, SMS template compliance (DLT), OEM-specific SMS permission behaviour, and sender ID consistency. Add WhatsApp OTP delivery as a parallel channel.
  • Depends on: Analytics ask O01 (OTP RCA by device/OEM/build).
  • Metric: Auto-read rate; OTP step completion; time to signup success.
  • Risk: OEM fragmentation means no single fix; fallback channel is the hedge.

U04 — Qualification-based goal flow + cohort search + popular on every layer

  • What: Replace the 180-category goal page with a qualification-first flow (Class 9–12, Dropper, Graduate, Working) that narrows categories per layer; every layer is a full page with a search bar and a "Popular for you" block.
  • Why: The largest drop after signup is on goal selection; a student exploring doesn't know which of 180 options maps to them. Qualification is the one thing every student knows.
  • Where: Goal selection.
  • How: Qualification → stream/exam → specific goal; search available at every level; popular options derived from cohort enrolment data and the Popular Exams work already done on category listing.
  • Depends on: Category taxonomy mapped to qualification; search index on goals.
  • Metric: Goal selection completion rate; time on goal page; D0 uninstall.
  • Risk: Mis-mapped qualification sends a student to the wrong listing — needs an easy "change goal" affordance.

U05 — Free content surfaced on batch listing

  • What: Show a free demo lecture, free test, or free notes at the top of the batch listing so the first screen after onboarding delivers something usable.
  • Why: ~10% of signups uninstall on the listing itself; they reached the right place but saw only paid batches. D0 value is the strongest anti-uninstall signal.
  • Where: Batch listing, first visit.
  • How: A "Start free" row above paid batches, cohort-specific, with one-tap play; content consumption counts as exploration.
  • Depends on: Free content tagged per cohort; player deep-link.
  • Metric: D0 content play rate; D0 uninstall on listing; soft activation.
  • Risk: Free content cannibalising paid intent — mitigate with limited depth (one lecture, not a chapter).

U06 — Android App Shortcuts hiding uninstall CTA

  • What: Register long-press App Shortcuts (e.g., "Free class today", "My batches", "Search") so the long-press menu shows offerings and pushes the uninstall option down.
  • Why: Many uninstalls happen via long-press; filling the menu with useful actions adds friction and a reminder of value.
  • Where: Launcher.
  • How: Static + dynamic shortcuts via ShortcutManager; dynamic shortcuts reflect the user's cohort.
  • Depends on: Nothing.
  • Metric: Uninstall rate (Android); shortcut tap rate.
  • Risk: Low impact per user; some launchers ignore shortcuts.

U07 — Early vernacular language selection

  • What: Ask preferred language (Hindi / English / regional) early and localise onboarding copy, batch titles, and pushes.
  • Why: Most users are tier 3–4; English-first onboarding is a comprehension barrier that looks like disinterest in the funnel.
  • Where: Immediately post-OTP or inferred from device locale with a one-tap confirm.
  • How: Device locale as default; one-tap language chip; localised strings for onboarding and comms templates.
  • Depends on: Translation of onboarding + top comms templates; batch metadata in Hindi where available.
  • Metric: Onboarding completion by language; D0 uninstall by locale.
  • Risk: Partial localisation feels broken — ship complete for Hindi first.

U08 — Marketing-campaign-based goal personalisation

  • What: Read the campaign / install referrer / onelink parameters and pre-fill or skip goal selection accordingly.
  • Why: A user arriving from a "NEET 2027 Dropper" ad should not be asked to pick from 180 categories.
  • Where: Goal selection.
  • How: Map campaign IDs → goal; show "We think you're preparing for NEET — correct?" with one tap to confirm or change.
  • Depends on: Attribution parameters surviving the install (Play Install Referrer, AppsFlyer/onelink); campaign→goal mapping maintained by marketing.
  • Metric: Goal completion for campaign traffic; D0 uninstall by source.
  • Risk: Wrong mapping sends users to the wrong listing; always show the confirm step.

U09 — Back-click intercept → Generic Offerings page + CLM win-back

  • What: On system or in-app back from name/goal screens, show a bottom sheet with one batch card; if tapped, land on a generic offerings page that works like guest checkout; if the user still leaves, run 3 CLM touches to D7 bringing them back to that page.
  • Why: Users who drop before goal selection never return organically; an intercept converts a leaving moment into a browsing moment, and the generic page removes the goal-selection barrier entirely.
  • Where: Name and goal screens; post-drop CLM.
  • How: Back-press handler → bottom sheet; generic page shows popular batches across cohorts with cohort chips; details captured only when the user moves deeper.
  • Depends on: Back-press instrumentation (O01); CLM templates.
  • Metric: Intercept → page tap rate; drop → return rate by D7.
  • Risk: Over-intercepting feels trapping — show once per session.

U10 — Low-end device health

  • What: Reduce APK size, cold-start time, ANRs and crashes on entry-level Android devices.
  • Why: Tier 3–4 users are on constrained devices and storage; a slow or crashing first session is an uninstall whatever the funnel says.
  • Where: Everywhere; most visible on first launch.
  • How: App Bundle optimisation, deferred module loading, startup tracing, crash-free session targets by device tier.
  • Depends on: Crash and performance data by device tier (O01 extension).
  • Metric: Crash-free sessions; cold start p75; uninstall by device tier.
  • Risk: Large effort with diffuse payoff — only prioritise if data shows a device-tier gap.

U11 — Pre-signup landing pages + onelink replacement

  • What: Marketing and YouTube onelinks land on a campaign-specific landing page (batch, teacher, price, CTA) before signup instead of dropping the user into generic onboarding.
  • Why: Users from a specific ad have a specific intent; showing the thing they clicked on before asking them to sign up raises both onboarding completion and conversion.
  • Where: Pre-signup, campaign traffic.
  • How: Landing page templates keyed by campaign; signup triggered from the batch CTA; goal pre-filled from the page.
  • Depends on: U08 attribution plumbing; coupon support on landing pages (already in coupon-system scope).
  • Metric: Landing → signup rate; signup → conversion for campaign traffic.
  • Risk: Adds a page before signup — must be fast and mobile-first or it becomes its own drop point.

U12 — Exit-intent micro-survey

  • What: One-tap "Why are you leaving?" with 3–4 options when a user backs out of onboarding.
  • Why: Cheapest way to learn the real drop reasons (can't find goal, too many steps, wrong app, just browsing) and calibrate everything else in this theme.
  • Where: Back-press on goal selection and listing.
  • How: Single-screen chips, optional, dismissible; answers logged per screen.
  • Depends on: Nothing.
  • Metric: Response rate; distribution of reasons.
  • Risk: None material; survey fatigue if shown more than once.

U13 — YouTube install nudge + per-video QR

  • What: Each YouTube video carries a unique QR / link; scanning personalises onboarding (goal, teacher, batch) to that video.
  • Why: YouTube is a primary top-of-funnel; a personalised landing from a specific lecture carries intent that generic onboarding discards.
  • Where: Pre-install → first launch.
  • How: QR → onelink with video ID → U11 landing page or U08 goal pre-fill.
  • Depends on: U08/U11; content team adding QR to video end-screens.
  • Metric: QR scans → installs → signup completion vs organic.
  • Risk: Reach limited to QR scanners; impact per user is high but volume is small.

U14 — Voice search + AI companion

  • What: Voice-first goal and batch search, plus an AI companion that answers "which batch is for me" in Hindi/regional languages.
  • Why: Voice and assistant adoption is high in tier 3–4; typing English goal names is a barrier.
  • Where: Goal selection and listing search.
  • How: Speech-to-text in Hindi + regional; intent mapping to goals; companion as a bottom-sheet chat.
  • Depends on: Search index; LLM/intent infra; the Voice Search prototype already on the shelf.
  • Metric: Voice search usage; goal completion for voice users.
  • Risk: High effort and uncertain lift; better framed as an activation/retention bet than an uninstall fix.

U15 — Gamified onboarding for dropped users

  • What: Users who dropped (and may have uninstalled) are offered coins for completing onboarding steps.
  • Why: Incentive-based re-entry can recover users with no organic intent.
  • Where: Win-back comms and re-entry flow.
  • How: CLM offer → re-install → coin-earning onboarding path; coins redeemable on paid SKUs (ties to P15).
  • Depends on: Coins economy; reaching uninstalled users (ads/retargeting, not push).
  • Metric: Re-install rate; onboarding completion for returners.
  • Risk: Reaching uninstalled users is expensive; incentive attracts low-intent users.

Theme 2 — Activation

A01 — Teacher filter promoted to top chip, other filters collapsed

O01 — Analytics asks

O02 — Batch propensity model

A score predicting purchase likelihood from exploration depth, cart events, cohort, source and season. Powers C06, C12, C20, C21, P07 and optionally C31 eligibility. Start with a rules-based score; graduate to a model once labelled data accumulates.

O03 — Frequency cap

1 push + 1 WA per user per day; ≤4 WA per week; event triggers count against the cap; in-app visit suppresses that day's scheduled push; 3 unopened pushes → WA-only at half frequency; 3 unopened WAs → silent until D30. Target ~14–16 scheduled touches over 30 days.

O04 — Per-step holdouts

10% holdout at each day-step of Loops A and B so each intervention's lift is attributable; a global 5% no-comms holdout for the overall programme.

O05 — Referral credit

Credit to the sharer when a friend purchases via a shared link (C27, C29). Redeemable only on higher-tier SKUs to double as an ARPU lever.

O06 — Real-time WA infra

Event-driven WhatsApp sends within minutes for cart abandon, payment failure and back-click; template library approved in advance; quality-rating monitoring.

O07 — ARPU data asks

Current FBT/add-on attach rate; plan-tier mix of buyers; checkout payment-failure rate. Sets ARPU baseline and Reach for C14/C22.

O08 — Payment failure data
